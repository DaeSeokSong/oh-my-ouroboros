## § 프롬프트 1회 = 사용자 보고 1회 — 근거

- 사용자 원문 (2026-07-29): "중간 보고 많으면 보기 힘드니까" — 알림마다 보고하면 한 요청에 보고 10회+가 발생해 결론이 묻힌다.
- 알림은 **main을 깨우는 신호이지 사용자 전달 내용이 아니다**. 내부 상태만 갱신하며 작업을 이어가고, 전부 끝난 뒤 하나로 취합해 보고한다(병렬 에이전트가 많을수록 강하게 적용).
- 금지 목록 전체: 트랙별 완료 보고 · "이제 하겠습니다" 예고 · 검증 통과 건건 알림 · teammate 유휴 알림 중계.

## § 알림 턴 물리적 감축 — 배경·근거 원문 (2026-07-29 공식 문서 조사로 확정)

배경: subagent 완료·idle·shutdown 알림은 **별도 대화 턴으로 주입**되며, 이를 억제하는 공식 설정·훅·응답 숨김은 존재하지 않는다(claude-code-guide 문서 조사: settings/env 키 없음, TeamMessage류 훅 이벤트 없음). 따라서 규칙이 아니라 **턴이 생기지 않는 운용**으로 막는다.

1. **동기 실행 기본 (2026-07-29 강화 — "아예 발생하지 말게")**: 위임은 `run_in_background: false` 가 기본이며 foreground는 알림 턴이 아예 생기지 않음(공식 문서 명시). background 예외는 1)사용자가 병렬을 명시한 경우 2)수십 분급 장기 작업 두 가지뿐이고, 이때도 발생할 알림 턴 수를 사전에 인지하고 감수 여부를 판단. 트레이드오프 정직 고지: 동기 실행 중에는 main이 블로킹되어 그 사이 사용자 신규 메시지 처리가 지연된다.
2. **해산은 TaskStop (핸드셰이크 전면 금지)**: shutdown_request는 요청당 알림 턴 2~3개(idle/terminated/approved)를 추가 유발. TaskStop은 알림 턴을 만들지 않음(2026-07-29 실측). 방치된 in-process 에이전트도 세션 종료 시 자동 정리되지만, 방치 중 유휴 알림이 재발할 수 있으므로 즉시 정지가 정본. (tmux teammate는 기존 패널 정리 절차 유지)
   - **주입 서문("Another Claude session sent a message…")의 성격 (2026-07-29 인터넷 전수 조사 확정)**: v2.1.181+(확인일 2026-10-17, 기준 Claude Code 2.1.301)에서 도입된 **permission laundering 방지용 하드코딩 보안 장치** — 끄는 설정·env·훅·커뮤니티 워크어라운드가 존재하지 않으며(공식 docs·GitHub 이슈·커뮤니티 3소스 일치), 보안 문구를 은닉·우회하는 시도는 해서는 안 된다. 대책은 오직 **메시지가 도착할 일 자체를 없애는 운용**뿐. 렌더링 축약 요청 이슈(#73647 등)가 5개월째 open — 향후 버전에서 완화될 수 있음.
3. **알림-전용 턴의 응답 최소화 (실측 보정)**: 알림-전용 턴은 **최단 1줄**로 고정하고 실보고는 사이클 종료 때 1회로 취합한다. 공백-전용 응답은 플랫폼이 거부함을 실측 확인(2026-07-29) — 완전 무출력은 불가, 발생원 감축(1·2항)이 본질 대책. 가시 텍스트 예: "(내부 처리 — 종합 보고에 취합)".
4. **spawn prompt 표준 문구**: "최종 보고는 SendMessage 1회로 완결하라 — 보고 전 idle 전환 금지, 보고 외 추가 메시지 금지"를 task_boundary에 포함해 에이전트발 잉여 턴을 원천 감축.
