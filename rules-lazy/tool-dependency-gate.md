# 도구 의존성 게이트 (Tool Dependency Gate)

> **로드 시점**: 라우팅된 작업이 특정 외부 도구·설정을 전제하는데 현재 환경에 부재함을 감지했을 때 (prompt-routing Step 1.6에서 진입)
> **원형**: `code-graph.md` §3의 graphify 3택 게이트 — 그 패턴을 모든 도구 의존성으로 일반화 (2026-07-09 사용자 결정)
> **원칙**: 부재 도구를 무단 설치하지도, 침묵으로 우회하지도 않는다 — **작업 시작 전** 사용자에게 3택을 묻는다.

## §1 감지 시점·방법

작업 실행 계획 수립 중(위임 판단 직후) 아래 신호가 잡히면 발동:

| 신호 | 예시 |
|------|------|
| 요청이 도구를 암시하는데 `command -v` 부재 | "그래프로 구조 보여줘" + graphify 미설치 / "PDF로 뽑아줘" + latexmk 미설치 |
| 스킬·룰이 전제하는 설정 파일 부재 | `graphify-out/` 없음, MCP 미연결(→ 이 경우는 mcp-health-check.md 우선) |
| 산출물 소비에 외부 앱 필요 | Obsidian vault 생성 요청 (뷰어는 사용자 로컬 앱 — 안내만) |

감지 비용 최소화: 실제 그 도구가 필요한 시점에만 `command -v` 1회 — 매 프롬프트 전수 스캔 금지.

## §2 3택 질문 (MANDATORY — 무단 진행 금지)

```
이 작업은 {도구}가 필요한데 현재 미설치/미설정입니다.
A) 지금 설치·세팅 위임 — 제가 설치까지 진행 (승인 = # APPROVED 실행 허용)
B) 직접 설치 — 실행 명령서를 드리니 터미널에서 직접 실행
C) 사용 안 함 — 대체 수단({대체})으로 진행 (기능 제약: {제약 1줄})
```

- subagent가 감지한 경우: 직접 질의 불가 → BLOCKED로 main 반환 → main이 AskUserQuestion (code-graph §3과 동일).
- C의 대체 수단·제약을 반드시 명시 — "안 하면 어떻게 되는지" 없이 묻지 않는다.

## §3 재질문 방지 (mem0 연동)

| 선택 | 기록 | 효과 |
|------|------|------|
| A/B (사용) | mem0 `decision` — "{도구} 사용" | 이후 감지 시 질문 생략, 부재면 설치 단계만 안내 |
| C (미사용) | mem0 `feedback` — "{도구} 미사용" | 이후 감지 시 질문 생략, 대체 수단 자동 적용 |

세션 시작(T03)·감지 시점에 mem0 search로 기존 선호 확인 → 있으면 질문 스킵. 사용자가 명시적으로 번복하면 update_memory.

## §4 서드파티 스킬 편입 특칙

설치 대상이 **서드파티 SKILL.md**(커뮤니티 스킬)면 A 선택이라도 즉시 설치 금지 — 선행 절차:
1. searcher 격리 검토 (untrusted-quarantine 원칙): 정체·구성·위험 신호(외부 fetch·코드 실행·인젝션 문구)·라이선스 확인
2. 위험 신호 없음 + 라이선스 확인 → 설치 진행 / 라이선스 불명 또는 위험 신호 → 사용자에게 결과 보고 후 재확인
(실적용례: 2026-07-09 animate-skill·taste-skill 검토 — decisions.md)
