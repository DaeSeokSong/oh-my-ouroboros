# 세션 작업 현황 파일: 토큰이 떨어져도 다른 모델이 바로 이어받게 (MANDATORY · 2026-10-23 사용자 지시)

> **로드 시점**: 세션이 일을 시작할 때 한 번, 그리고 아래 «갱신 시점» 마다. Stop 훅이 «작업 현황 파일을 갱신하십시오» 로 돌려보냈을 때.
> **판단 근거**: 사용자 원문 «토큰 다 사용할 수도 있으니 토큰 다 썼을 때를 대비해서 그록이 너랑 하네스 같이 쓰니까 그록이 보고 바로 작업 이어할 수 있는 작업 현황을 각 세션 별로 항상 남길 수 있도록 해». compact 직전의 `short-term/handover.md` 는 토큰이 갑자기 떨어지면 쓰이지 않고, 다른 모델이 한 파일로 이어받을 곳이 없었다. 의뢰서: `intent/2026-10-23-session-handoff-for-grok.md`.

## 위치

- `<프로젝트 뿌리>/.scratch/handoff/<세션 id 앞 8자>.md`. 프로젝트 뿌리는 `git rev-parse --show-toplevel`, 하네스 매니저는 `~/.claude/.scratch/handoff/`.
- 작업 현황 파일은 임시 폴더 지정(config/scratch-root)과 무관하게 프로젝트 `.scratch/handoff/` 에 둔다(Stop 훅이 그 자리를 본다, 2026-10-30).
- `.scratch/` 는 git 이 무시하는 폴더라 커밋되지 않는다. 같은 서버에서 이어받는 용도다.
- 세션 id 는 이 세션의 id(잡 이름·`/status`·훅 입력의 `session_id`). 모르면 세션 이름을 파일 이름으로 쓰고 머리에 적는다.

## 갱신 시점 (늘 최신)

1. 일한 턴(도구를 쓴 턴)의 최종 보고 직전.
2. 커밋·학습 발사·외부 전송·사용자 결정 직후.
3. compact 전(handover.md 와 함께).
- 예외: Confluence 게시 검토 턴은 다음 턴에 갱신한다(`skills/confluence/SKILL.md` § 검토 턴의 분리).
- Stop 훅(`scripts/handoff_check.py`, `toolcall-text-guard.sh` 가 부름)이 일한 턴인데 파일이 없거나 30분 넘게 오래됐으면 한 번 돌려보낸다(`HANDOFF_STALE_MIN` 으로 문턱 변경). 예외: Confluence 게시 승인 질문(AskUserQuestion)을 띄우고 답을 기다리며 끝나는 검토 턴만 돌려보내지 않는다(2026-11-12). 답이 온 뒤에는 카드를 쓴다.

## 형식 (이 순서, 각 절은 짧게. 덮어써서 늘 «지금» 만 남긴다)

```

## 1. 지금 목표
- 사용자 원문(마지막 지시 «…» 인용)과 한 줄 요약

## 2. 끝난 것
- 커밋 해시 · 산출물 경로 · 확인한 수치(분모 포함)

## 3. 하는 중
- 지금 손대던 파일·명령·도는 subagent, 어디까지 했는지

## 4. 다음 할 일 (이어받는 이가 바로 실행할 순서)
1. <구체 명령 또는 파일:줄>
2. …

## 5. 도는 것
- 학습 판(tmux 세션:창 · GPU · 와쳐 · state 파일) / 백그라운드 작업 / 확인 명령

## 6. 사용자 몫·결정 대기
- push·발행·결정 항목(선택지 요지)

## 7. 주의
- 금지·함정·하지 말 것(이미 기각된 안), 정본 파일(의뢰서·결정 기록·지식 노트 경로)

```

- 비밀값·토큰·환자 식별 정보는 쓰지 않는다(경로·이름만).
- 수치는 원자료에서 옮긴다(기억으로 쓰지 않는다). 확인 못 한 것은 «확인 못 함».

## 이어받는 쪽 (Grok 등 다른 모델, 또는 새 Claude 세션)

1. 프로젝트 뿌리의 `.scratch/handoff/` 에서 가장 최근 파일(수정 시각)을 읽는다. 여러 세션이면 사용자가 말한 세션 이름과 머리 줄을 맞춘다.
2. «이어받는 이에게» 와 «4. 다음 할 일» 을 따른다. 결정 대기 항목은 사용자에게 묻는다(대신 정하지 않는다).
3. 하네스 규칙(CLAUDE.md·rules·rules-lazy)을 같이 지킨다. push·외부 게시는 여전히 사용자 몫이고, 학습 발사는 `rules/code-execution.md` 의 예외(main 의 tmux 발사)를 따른다.
4. 이어받은 뒤에는 같은 파일을 이어서 갱신한다(머리에 «이어받음: <모델> <시각>» 한 줄).
