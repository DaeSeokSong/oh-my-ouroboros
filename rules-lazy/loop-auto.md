# Loop Auto-Trigger — 반복 실행 패턴

> **로드 시점**: 반복 루프 패턴이 필요한 작업 시작 전 (학습 모니터링 감지, /loop 호출, Ralph 트리거, G-E Loop 진입 시)
> **비용 모델**: Pro/Max 구독 토큰만 (추가 비용 없음)
> **흡수 통합**: `generator-evaluator-loop.md` 내용을 이 파일이 완전 흡수. 해당 파일 삭제됨.

---

## 3+1 loop 패턴 비교표

| 패턴 | 스킬/명령 | 페이싱 | 주요 용도 | 종료 조건 |
|------|---------|--------|---------|---------|
| **Interval `/loop`** | `/loop interval=5m` 등 | 고정 (5m / 30m / 1h) | wandb 학습 모니터링, PR 상태 babysit | 사용자 중단 또는 목표 달성 |
| **Dynamic `/loop`** | `/loop dynamic` | 자가 페이싱 (이전 결과 기반 조정) | CI 대기, deploy 점검, 비동기 작업 완료 감지 | 조건 충족 시 자동 종료 |
| **Ralph Wiggum** | `ralph-loop:ralph-loop` | 테스트 FAIL 시마다 | qa 테스트 자동 재시도, import/경로 오류 반복 수정 | PASS 또는 위임 한도 초과 |
| **G-E Loop** | (내장 — 스킬 없음) | coder ↔ qa 메시지 교환 라운드 | coder 수정 → qa 검증 → 재수정 자동화 | 3회 초과 → main 에스컬레이션 |

## G-E Loop 자동 진입 조건

G-E 루프는 아래 조건 **모두** 충족 시 자동 진입한다:

| 조건 | 기준 |
|------|------|
| FAIL 위치 명확 | `{파일}:{라인}` 단위로 특정 가능 |
| FAIL 원인 명확 | 단일 지점 수정으로 해결 가능 (아키텍처 변경 ❌) |
| 재시도 횟수 < 3 | 동일 파일·함수 기준 |
| 동일 원인 < 2회 연속 | 무한 루프 방지 |

> **이중 카운터 (병행)**: 총 재시도 상한 3회(원인 불문) + 동일 원인 2회 연속 시 **조기** 에스컬레이션 — 후자는 상한이 아니라 조기 종료 조건. coder.md·qa.md의 동일 서술과 한 설계다. (Ralph 루프의 동일 원인 3회 기준과는 별개 루프)

미충족 시 → main 에스컬레이션 (자동 재시도 ❌)

---

## G-E ↔ Ralph 우선순위

FAIL 발생 시 아래 순서로 판단:

| 우선순위 | 조건 | 처리 |
|--------|------|------|
| 1 | G-E 자동 진입 조건 **모두** 충족 | G-E 루프 진행 |
| 2 | G-E 조건 미충족 + 사용자가 Ralph 명시 | Ralph 루프 (`ralph-loop:ralph-loop`) |
| 3 | 둘 다 부적합 | main 에스컬레이션 |

## 호출 명령

```bash
# Interval 루프 (5분 간격)
/loop interval=5m target="wandb 학습 모니터링"

# Dynamic 루프 (자가 페이싱)
/loop dynamic target="CI 완료 감지"

# Ralph Wiggum 루프 (아래는 플러그인 스킬 이름이다. 사용자 입력은 /ralph-loop 래퍼 command, qa 자율 진입은 5-Gate 통과 후)
ralph-loop:ralph-loop

# G-E Loop (자동 진입 — 별도 명령 없음)
# qa FAIL 보고 수신 시 coder가 자동으로 G-E Loop 진입
```

## G-E Loop 흐름도

```
[main 요청]
  ↓
[scout 정찰] → 파일 목록·라인 정보
  ↓
[coder] 수정 적용 → "수정 완료" 보고
  ↓
[scout QA정찰] → 영향 범위
  ↓
[qa Evaluator] 검증
  ├─ PASS → main 보고 (루프 종료)
  └─ FAIL → "Evaluator Feedback" 섹션 + 구체 수정 지시 출력
                ↓
              [coder Generator] 재시도 (직접 Edit)
                ↓
              [qa Evaluator] 재검증
                ↓
              ↑ 최대 3회 반복 ↑
                ↓
              3회 초과 → main 에스컬레이션 또는 Ralph Wiggum 트리거
```

## main 에스컬레이션 형식

G-E Loop 종료 시 (3회 초과 또는 조건 미충족):

```
⚠️ G-E Loop 종료 (자동 해결 실패):
- 파일: {파일}:{함수}
- 시도 횟수: N/3
- 최종 FAIL 원인: {요약}
- 권장 조치: {예: 아키텍처 변경, 사용자 결정 필요, Ralph Wiggum 트리거}
```

## G-E vs Ralph 비교

| 항목 | Ralph Wiggum | Generator-Evaluator |
|------|-------------|---------------------|
| 트리거 | 동일 작업 prompt 반복 (FAIL 원인 모름) | 검증 결과 + 구체 수정 지시 (FAIL 원인 명확) |
| 정밀도 | 낮음 (시도 위주) | 높음 (피드백 기반) |
| 횟수 제한 | N회 (사용자 설정) | 3회 (고정) |
| Mem0 source | `qa-ralph` | `generator-evaluator` |
| 카테고리 | `code_pattern` | `code_pattern` |

G-E 3회 실패 시 → Ralph Wiggum 트리거 또는 main 에스컬레이션 선택.
