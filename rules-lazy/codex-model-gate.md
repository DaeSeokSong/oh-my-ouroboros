# Codex 모델·Effort 선택 게이트

> **로드 시점**: codex 위임 직전 — 사용자가 `/codex:rescue` 입력, main이 `codex:codex-rescue` spawn, 또는 직접 `codex exec` 사용 시 (agent-routing § 소집 도구 선택 기준에서 진입)
> **원칙 (2026-07-10 사용자 결정, 2026-09-28 단위 재정의)**: **작업 사이클마다** 모델·effort를 보기로 물어본다 — 원하는 모델이 사이클마다 다를 수 있으므로 mem0 기억으로 질문을 생략하지 않는다. `~/.codex/config.toml`의 기본값은 같은 날 제거됨(기본값이 있으면 "안 묻고 기본값 실행"이 조용히 일어나기 때문 — 게이트가 항상 명시 전달하므로 기본값 무의존). **사이클** = 실제 사용자 메시지 하나가 촉발해 그록·코덱스를 여러 번 부르고 최종 보고로 끝나는 구간(§2.1 예외 참조) — 개별 호출 단위가 아니다.

## §0 실행 컨텍스트 사전 검사 (MANDATORY — 2026-08-25 실사고로 신설)

> **§1 질문보다 먼저**다. 질문은 "무엇을 보낼지"를 정하고 이 절은 "무엇이 닿을 수 있는지"를 막는다. 둘은 다른 층이다.

**원칙**: codex 는 지시받은 텍스트만 읽는 도구가 아니라 **작업 폴더를 스스로 뒤지는 에이전트**다. 따라서 검사 대상은 payload 가 아니라 **그 도구가 닿을 수 있는 트리 전체**다.

**사고 경위 (근거 이식)**: 2026-08-25 한 프로젝트 추론 서버 저장소의 교차검증에서 검토 묶음을 조립해 9개 패턴으로 훑어 0건을 확인하고 보냈다. 그런데 codex 가 실행 폴더 안의 민감 자료를 스스로 찾아 읽어 **외부로 전송**됐다. 묶음 검사 통과가 오히려 "안전하다"는 오판을 굳혔다. `--skip-git-repo-check` 는 git 검사를 건너뛸 뿐 탐색을 막지 않는다.

**절차 (3단 모두 필수)**

1. **트리 검사**: `python3 ~/.claude/scripts/external_send_preflight.py <작업디렉터리>` — 차단 0건이어야 진행. UID·DB 접속 문자열·개인키·AWS 키·자격증명 대입을 잡는다. 차단이 나오면 보내지 말고 폴더를 바꾼다.
2. **작업 루트 못박기**: `codex exec ... -C <깨끗한 폴더> -s read-only` — `--cd` 없이 돌리면 **현재 폴더가 루트**가 된다. 이 두 플래그를 뺀 호출은 금지.
   - **read-only 는 쓰기만 막는다**: 읽기 범위는 막지 않아 절대 경로로 폴더 밖을 읽을 수 있다(코덱스 `-s read-only`·그록 `--sandbox read-only` 공통, 그록 공식 문서 18-sandbox 표). 그래서 3번(깨끗한 폴더)과 1번(트리 검사)이 필요하며, 1번은 1차 점검이지 충분 조건이 아니다.
   - **MCP·플러그인 끄기 (2026-09-28 사용자 결정 3-1)**: `~/.codex/config.toml` 에 mem0·tavily·context7 MCP 와 Atlassian·Linear 플러그인이 전역 등록돼 있어 모든 코덱스 세션에 열린다. 직접 exec 호출에는 아래를 붙인다. 서버별로 끄는 이유는 `-c 'mcp_servers={}'` 가 병합돼 무효이기 때문이다(`codex mcp list` 실측).
     `-c mcp_servers.mem0.enabled=false -c mcp_servers.tavily.enabled=false -c mcp_servers.context7.enabled=false --disable apps --disable plugins`
     config.toml 에 MCP 서버를 새로 등록하면 이 줄에도 추가한다. 확인은 같은 `-c` 를 붙인 `codex mcp list` 가 전부 `disabled` 인지 본다.
   - **한계**: `/codex:rescue` 플러그인 경로는 app-server 를 이 설정 없이 띄우므로 MCP 가 열린 채로 돈다(플러그인 1.0.6 코드 확인).
3. **필요한 것만 복사**: 민감 자료가 있는 폴더에서 직접 돌리지 않는다. 전용 폴더를 만들어 검토에 필요한 소스만 넣는다. 근거 번들(`docs/**/results/` 등)은 기본 제외.

**경계**: 1번 통과는 "아는 위험 패턴이 없다"는 뜻이지 안전 보장이 아니다. 패턴에 없는 형태의 식별자는 못 잡는다.

**검사 범위와 호출 형태 (2026-10-01 감사 반영)**
- 사전검사는 파일 내용뿐 아니라 **파일·폴더 이름**과 목록 밖 확장자의 파일도 본다(식별자가 이름에 든 트리를 통과시키던 구멍을 막는 구현이 반영됐다: `external_send_preflight.py`. 폴더 심볼릭 링크도 «미검사» 로 세어 차단한다). 이름에 식별자가 든 파일은 깨끗한 폴더로 옮기지 말고 제외한다.
- **`-C` 없는 `codex exec` 는 훅이 거부한다.** 작업 루트를 못박지 않으면 훅이 검사한 트리와 실제 루트가 달라지기 때문이다(`cd X && codex exec …` 도 같다). 위 절차 2번의 `-C <깨끗한 폴더>` 는 훅 통과용 옵션이 아니라 이 절의 필수 조건이다.
- **`-C` 절대 경로·프롬프트 본문 비밀값 검사 (2026-10-17)**: `codex exec -C` 는 절대 경로만 허용하고(상대·`~`·`$HOME` 거부), 프롬프트 문자열도 고신뢰 비밀값 패턴(`sk-`·`AKIA`·`xox[bp]-`·`ntfy.sh/`·개인키)으로 훑어 걸리면 훅이 거부한다. 한계: 본문 검사는 명령문의 리터럴만 본다. `$(cat …)`·변수·stdin·분할 문자열·codex 플러그인 경유 프롬프트는 못 본다.
- **플러그인 companion 의 하위 명령도 외부 전송이다**: `codex-companion.mjs` 의 `review`·`adversarial-review`·`transfer`(와 `task`)는 전부 작업 트리를 OpenAI 로 보내므로 같은 모델·effort 게이트(사이클당 1회)와 위 사전검사의 대상이다. 훅이 어떤 하위 명령까지 분류하는지와 무관하게 이 규칙을 적용한다.

**Grok 도 동일 적용**: 래퍼(`tools/grok-exchange/grok-ask.sh`)는 HOME 을 호출별 빈 폴더로 바꾸고 `--sandbox strict` 를 고정한다. 읽기 도구는 있지만 읽기 범위가 그 빈 폴더와 시스템 경로뿐이다. 예외를 두지 않는다 (`skills/grok/SKILL.md` Step 1.5 와 한 쌍).

**Grok 직접 호출 금지 (HARD BAN — 2026-09-28 사용자 결정)**: `grok`·`~/.grok/bin/grok` 을 래퍼 없이 실행하지 않는다. subagent·피어 세션도 같다.
- 왜: 그록의 Claude 호환 모드는 기본으로 켜져 있어 cwd 와 무관하게 `~/.claude/CLAUDE.md`·`rules/`·`skills/`·`~/.claude.json`(MCP 정의)을 매 세션 싣는다(그록 공식 문서 12-project-rules). 샌드박스 기본값은 off 다(18-sandbox). `--tools ""`·`--disable-web-search` 를 둘 다 줘도 도구 24개가 살아 있었다(09-28 피어 세션 실측, 문서 명시 없음).
- 호환 모드는 끄지 않는다(사용자 결정 2-2). 대화형 그록에서 하네스 규칙을 쓰기 위해서다. 방어는 이 금지 규칙과 래퍼가 맡는다.
- 모델 게이트 훅(`scripts/external-model-gate.py`)은 래퍼 이름만 알아보므로 직접 호출은 훅이 잡지 못한다. 기계 차단은 두지 않기로 했다(사용자 결정 1-2).

### §1.1 학습 위장 규약 (2026-07-11 사용자 승인)

목적: 민감한 개인 연구를 어쩔 수 없이 외부 검증에 보낼 때, "연구 아이디어"가 아니라 "공부 중인 내용"으로 보이게 재포장하되 **원하는 검증 정보는 온전히 얻는다**.

- **프레임**: "교재/수업 과제/연습문제에서 본 유도인데 스스로 이해·검증하려 한다" — 익명의 학습 맥락.
- **권위 편향 방지 (품질 핵심)**: 실존 논문·유명 기법을 사칭하는 프레임 금지 — "알려진 기법 공부 중"이라고 하면 검증자가 '기존 결과니 맞겠지'로 비판을 늦춘다. 반드시 **비판 유지형 요청**으로: "이 유도에 오류나 빈 구멍이 있는지 찾아달라", "반례가 가능한 조건은?"
- **연결성 절단(선택)**: 질문이 여러 개면 작은 독립 질문으로 쪼개 전송 — 전체 그림의 재구성 가능성을 낮춘다 (쪼갰는지 여부는 최종 보고에 함께 적는다).
- **한계 정직 고지**: 위장은 의도·맥락의 연결을 숨기는 것이지 전송된 골격 내용 자체의 서버 보존(§3.5)을 없애지 않는다 — 골격 그 자체가 신규성의 핵심이면 위장으로도 보호되지 않으므로, 그 경우 '취소 → 내부 검증'을 권한다.

## §2 전달 규약 — 직접 exec 기본, 플러그인은 대체 (2026-11-12 사용자 결정, 종전 2026-07-10 플러그인 기본)

## §2.2 세션 재사용·교환 폴더 정리 (2026-09-08 사용자 결정)

이어지는 작업은 **새 세션을 파지 말고 같은 세션을 재개한다**. 맥락을 다시 실어 보내는 전송량과 그때 딸려 가는 정보를 줄이는 것이 목적이다.

| 대상 | 이어쓰기 명령 |
|------|---------------|
| Grok | `~/.claude/tools/grok-exchange/grok-ask.sh --session <주제이름>` (ID 는 `~/grok-exchange/.sessions/`) |
| Codex | `codex exec resume [SESSION_ID] [PROMPT]` — SESSION_ID 는 UUID 또는 thread 이름이고 생략하면 `--last` 로 최근 세션을 잇는다. 목록에 cwd 필터를 풀려면 `--all` |

`codex exec resume --help` 원문: `Resume a previous session by id or pick the most recent with --last` / `Usage: codex exec resume [OPTIONS] [SESSION_ID] [PROMPT]`.

**게이트는 그대로다**: 이 §2.2 의 「세션 이어쓰기」는 **다른 사이클**(다른 실제 사용자 메시지)에서 --session/resume 으로 대화를 잇는 경우를 말하며, 이때는 모델·effort 질문을 다시 한다(2026-09-08 사용자 확인). 세션 재사용은 전송 내용을 줄이는 장치이지 승인을 물려받는 장치가 아니다. **같은 사이클 안의 반복 호출**(아직 최종 보고 전, 같은 실제 사용자 메시지 구간)은 §2.1 의 「사이클 내 반복 호출 재사용」 예외가 적용돼 다시 묻지 않는다 — 둘의 경계는 실제 사용자 메시지가 새로 왔는지 여부다.

**정리**: `scripts/exchange-prune.sh` 가 SessionStart 에서 `~/grok-exchange`·`~/codex-exchange` 아래 **14일 이상 손대지 않은** 실행 폴더와 패킷을 지운다(기한은 `EXCHANGE_PRUNE_DAYS`, `--dry-run` 으로 미리보기). 이름이 `.` 으로 시작하는 항목은 지우지 않으며 세션 ID 를 담은 `.sessions/` 가 여기 든다. 지우면 위의 이어쓰기가 깨지기 때문이다.

## §4 게이트가 막지 못하는 것 (2026-09-06 security 검수 실측)

`scripts/external-model-gate.py` 는 명령 문자열의 접두를 보고 외부 모델 호출을 알아채는 방식이라 아래는 통과한다.

- 래퍼 속 래퍼: 알려진 래퍼가 다시 다른 스크립트를 부르는 깊이 2 이상의 호출
- 다른 언어 래퍼: 파이썬·노드 등으로 감싼 실행
- `bash -c "…"` 인용 실행, `eval`·`source` 경유 실행
- 접두 목록 밖 명령 이름, 변수로 조립해 만든 명령 이름

**래퍼에는 모델·effort 를 리터럴로 적는다 (2026-09-06 오탐 실측)**: 긴 호출을 래퍼 `.sh` 로 띄울 때 모델·effort 를 셸 변수로 넘기면 게이트가 래퍼 안을 읽고도 값을 못 풀어 `model=$MODEL` 로 비교하다 차단한다. 사용자가 보기에서 고른 값을 그 자리에 직접 적어야 게이트가 검사할 수 있다. `-C`(codex)·`--file`(grok) 경로도 리터럴로 적는다. 게이트가 `-C` 값에 preflight 를 돌리므로 변수면 «없는 경로»로 차단된다(2026-09-08 실측).

커밋 게이트도 마찬가지로 `git commit --no-verify` 나 `git -c core.hooksPath=` 로 우회되며 그 우회는 감사 원장에 남지 않는다.

이 게이트는 기억 대신 서 주는 1차 방어선이지 우회 불가 통제가 아니다. 따라서 모델·effort 를 사이클마다 묻는 규칙(§1) 자체는 계속 유효하며, 사이클을 넘어 훅 통과를 근거로 질문을 건너뛰지 않는다(같은 사이클 안의 반복 재사용은 §2.1 예외).
