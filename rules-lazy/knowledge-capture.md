# 대화 지식 → 온톨로지 축적 (knowledge capture)

> **로드 시점**: 대화 중 재사용 가능한 지식이 확정되는 순간(§2 트리거), 또는 usage-check `KNOWLEDGE_SILENT` 경보 시.
> **원 지시 (2026-07-13 사용자 교정)**: "사용자가 어떤 프롬프트를 입력하던 옵시디언 온톨로지에 해당 대화에서 지식을 추출하여 쌓일 수 있도록". 온톨로지가 하네스 *파일*만 그래프화하고 *대화*는 버리던 것은 설계 오해였다 — 이 룰이 그 경로를 복원한다.

## §1 경로 설계 (왜 vault 직접 쓰기가 아니라 knowledge/인가 — 판단 근거)

vault(`graphify-out/obsidian/`)는 graphify export가 **재생성하는 파생물**이다 — 거기 직접 쓴 노트는 다음 빌드에서 유실·고아화된다. 그래서 지식은 **코퍼스(원천)** 에 넣는다:

```
대화 중 지식 확정 → main이 knowledge/<프로젝트>/<slug>.md 노트 즉시 작성 (파일로 축적 — 실시간)
→ 일간 타이머(ontology-refresh, 매일 03:17 — 2026-07-13 주간→일간)가 시맨틱 추출 → 그래프 노드 + vault 노트로 편입 (그래프 반영은 최대 1일 + push 대기 시간)
```

- **즉시 가시성**: Obsidian에서 `~/.claude`를 vault 루트로 열면 `knowledge/`와 `graphify-out/obsidian/`이 함께 보이고, 위키링크는 파일명 기준으로 폴더를 넘어 해석된다.
- **in-session 캡처를 택한 이유**: 세션 종료 후 트랜스크립트 마이닝(훅+헤드리스 Claude)보다 ① 토큰이 싸고(대화 재읽기 없음 — main이 이미 맥락 보유) ② 품질이 높다(무엇이 지식인지 main이 판정 가능). 룰 의존의 준수 리스크는 usage-check `KNOWLEDGE_SILENT`(14일 무산출 경보)가 감시한다 — 구축-미사용 rot(#5)의 "event-구동 인프라 + 신선도 감시" 처방.

## §2 트리거 — 무엇이 "지식"인가

| 캡처 ○ | 예 |
|--------|-----|
| **실측 발견** — 디버깅 근본원인, 실험으로 확인된 사실 | "신모델 거부의 진범은 stale broker 데몬" |
| **도메인 사실 확정** — 외부 검증 완료된 사실관계 | "Codex ChatGPT 로그인은 학습이 기본값" |
| **설계 근거** — 트레이드오프 판단의 이유 (결정 자체가 아니라 이유) | "vault는 파생물이라 코퍼스 경유가 맞다" |
| **채택/기각 판단이 내려진 외부 지식** — 논문·자료 평가 결론 | "EvoPolicyGym 구조/조정 구분 이식" |

| 캡처 ✗ | 이유 |
|--------|------|
| 일회성 상태·실행 로그·진행 상황 | 재사용 불가 — 지식이 아니라 이벤트 |
| 합의 결정 자체 | `decisions.md` 소관 (단, 결정의 **일반화 가능한 근거**는 캡처 ○) |
| 시크릿·자격증명·개인 연구의 신규성 핵심 | 보안 — repo에 남기지 않는다 |
| 프로젝트 코드 자체의 지식 | 해당 프로젝트의 graphify 그래프 소관 |

판정 휴리스틱 1줄: **"6개월 뒤 다른 세션이 이 문장을 몰라서 같은 삽질을 반복할 수 있는가?"** — YES면 캡처.

## §3 노트 스키마

파일: `~/.claude/knowledge/<프로젝트>/<kebab-slug>.md` (슬러그 영문, 본문 한글)

**프로젝트 폴더 규약 (2026-07-14 사용자 지시 — 프로젝트별 관리)**:
- `harness/` — 하네스·Claude Code 운영 지식 (훅·타이머·권한·statusline·headless 등)
- `<프로젝트-슬러그>/` — 해당 연구 프로젝트의 도메인 지식 (예: `modularnet/`)
- 배정 기준 1줄: **"이 지식을 재사용할 세션이 어느 프로젝트에서 뜨는가"** — 애매하면(양쪽에서 재사용) `harness/`
- `README.md`만 루트 유지. 신규 프로젝트 폴더는 첫 노트 작성 시 그냥 만들면 된다 (등록 절차 없음 — detect가 하위 폴더 재귀 수집, 실측 확인)
- 폴더는 **사람 브라우징 + vault 노트의 `source_file` 메타데이터 그룹핑**용이다 — Obsidian Graph View는 링크 기반이라 폴더 무관, 서버별 폴더는 금지(서버는 주제가 아니라 출처 — frontmatter `source:` 소관, 폴더로 나누면 서버 간 동일 지식이 중복됨)

**프로젝트명 확인 게이트 (MANDATORY — 2026-07-14 사용자 지시)**: 노트 작성 전 배정 폴더를 사용자에게 확인받는다 — 배정 추정이 틀린 채 온톨로지에 편입되는 것 방지.
- 형식: "이 지식을 `knowledge/<프로젝트>/`에 기록하려 합니다 — 맞나요? (다른 이름을 답하시면 그 폴더로, 없으면 생성)" — 같은 턴의 복수 노트는 **한 번에 목록으로** 질문 (건별 반복 질문 금지). AskUserQuestion 사용 시 선택지 = 제안 폴더 + 기존 폴더 목록 + Other.
- **세션 내 재확인 생략**: 같은 세션에서 동일 프로젝트 배정이 한 번 확정되면 후속 노트는 질문 없이 동일 배정 + 보고만.
- **무인 컨텍스트 예외** (헤드리스·백그라운드 등 질문 불가): 추정 배정으로 즉시 작성하되 보고에 `(배정: <프로젝트> — 수정 원하시면 말씀)` 명시.
- **사후 수정 항상 가능**: 사용자가 배정·폴더명 수정을 요청하면 `git mv`로 즉시 반영 — 캐시 키가 내용+상대경로라 이동 노트는 다음 빌드에서 1회 재추출됨을 고지.

```markdown
---
title: 한 줄 제목
date: YYYY-MM-DD
type: finding | fact | rationale | adopted-knowledge
tags: [영역, 도구명, ...]
source: 대화 | arXiv:NNNN.NNNNN | URL | 실측
---

지식 본문 1~4문장 (결론 선행).

**근거**: 어떻게 확인됐는가 (실측 명령·문서·논문 섹션).
**연결**: [[관련-노트]] [[하네스 문서 파일명]]
```

## §4 중복 방지 · 경계

- 작성 전 `Glob knowledge/**/*.md`로 동일 주제 노트 확인 — **프로젝트 폴더 무관 전역 검사**(같은 지식이 두 폴더에 중복 생성되는 것 방지). 있으면 **update**(새 사실은 본문에 날짜와 함께 append), 새 파일 금지.
- **mem0와 이중 저장이 아니다**: mem0 = 검색 회상용(SaaS, 세션 복원), knowledge/ = 온톨로지 그래프 노드용(위키링크 연결·시각화·영구 repo). 소비자가 다르다. 다만 같은 문장을 두 곳에 그대로 복사하는 대신, mem0에는 이벤트 맥락을·knowledge에는 일반화된 지식만.
- 노트는 1건 1지식 — 여러 지식이 한 대화에서 나오면 노트를 나눈다 (그래프 노드 단위 = 지식 단위).
