# 코드 위치·프로젝트 경계 상세 (code-execution 보조)

> **로드 시점**: 임시·최종 코드의 저장 위치를 정할 때, 또는 다른 저장소가 관련될 때
> **성격**: `rules/code-execution.md` § 프로젝트 경계·§ 코드 저장 규칙(폴더 사전 지정 괄호 포함)의 **정본 상세**. always-on 에는 골자만 남기고 절차·근거·실사고를 이 파일로 무손실 이관했다(2026-09-08 예산 다이어트, 내용 삭제 0). 날짜 붙은 사용자 지시는 그대로 보존한다.

## § 프로젝트 경계 (2026-09-07 사용자 지시, 예외 없음)

- **쓰기는 현재 프로젝트 저장소 안에서만**: cwd 가 속한 저장소(예: `~/workspace/research/<프로젝트 A>`)가 유일한 쓰기 대상이다. 다른 프로젝트 저장소(예: `~/workspace/engine/<프로젝트 B>`)는 **Read·Grep·Glob 만** 허용한다. Write·Edit·파일 생성·삭제·`git checkout`·`git stash`·설정 파일 변경·테스트 파일 추가 전부 금지다.
- **«scripts 에 만들어» = 현재 프로젝트의 `scripts/`**: 산출물 위치가 모호하면 다른 저장소가 아니라 현재 프로젝트 안의 폴더로 해석한다. 다른 프로젝트에 넣어야 할 이유가 보이면 만들지 말고 사용자에게 묻는다.
- **다른 프로젝트 수정이 필요해 보일 때**: 현재 프로젝트 쪽에 같은 기능을 스크립트로 만들고, 다른 프로젝트에 필요한 변경은 «그 프로젝트를 열었을 때 할 일»로 보고에만 적는다.
- **subagent 전파**: coder·qa·scout spawn prompt 의 task_boundary 에 «다른 저장소는 읽기만, 수정 금지»를 그대로 적는다. main 이 경계를 안 적어 subagent 가 넘어간 것도 main 의 위반이다.
- **집행**: `scripts/scope-gate.sh` 가 Write·Edit 대상이 cwd 저장소 밖의 다른 git 저장소면 차단한다(scope 등록과 무관). Bash 경유 리다이렉션은 `bash-write-check.sh`가, `git checkout .`·`restore .`·`stash`(2026-09-14 추가)는 `git-guardrails.sh`가 막는다. 다만 두 훅 다 저장소 경계는 모르므로 저장소 밖 일반 파일을 포함한 **「저장소 밖 쓰기」**에 한해서는 always-on 의 문구가 유일한 통제다.
- **같은 저장소의 워크트리**: cwd 저장소의 git 워크트리는 폴더가 저장소 밖(임시 디스크 등)에 있어도 같은 저장소로 보아 쓸 수 있다(2026-11-21 사용자 결정, `scripts/scope-gate.sh` 의 `same_repo_worktree`). 다른 저장소의 워크트리는 종전대로 읽기만 된다. 학습이 도는 워크트리의 코드는 고치지 않는다(훅이 구분하지 못한다).
- **기록 정본 예외 (2026-09-08 사용자 결정)**: `~/.claude/projects/<프로젝트>/memory/` 아래는 하네스의 자기 기록이라 경계 대상이 아니다(훅 메타 예외). **임시 스크립트는 이 예외에 들지 않는다**(아래 § 임시 코드).
- **하네스 홈 쓰기 (사실 그대로 기록, 2026-10-01 감사, 2026-10-17 현재 동작으로 개정)**: `~/.claude/` 아래 경로는 기본값이 `[Harness] Manager` 세션 전용이다(cwd 와 무관, 열거 목록이 아니라 기본 거부). 모든 세션이 쓸 수 있는 곳은 `projects/<프로젝트>/memory/`·`knowledge/`·`doc-formats/`·`_evolve/quiz/`·`.scratch/`·자기 `scope/<session_id>.json` 뿐이다. 그래서 `knowledge-capture.md`·`doc-format-registry.md` 가 시키는 `knowledge/<프로젝트>/` 노트·`doc-formats/` 양식 등록은 다른 프로젝트 cwd 에서도 쓴다. 매니저도 못 쓰는 항상 차단은 `sessions/`·`_usage/`·후보 대장 4파일(`_evolve/` 의 candidates.tsv·candidates.lock·crosscheck.tsv·prompts.jsonl)·`.git/`·남의 `scope/` 파일·`_audit/publish-approval/`·`projects/*/*.jsonl` 이다. `jobs/`·`teams/`·`daemon*`·`projects/` 의 memory 밖 경로는 아래 프로젝트 경계 검사로 간다. 전원 허용 폴더는 하네스 자기 기록용이므로 하네스의 룰·스킬·스크립트를 다른 프로젝트 작업의 부산물로 고치는 근거로 쓰지 않는다. 정본은 `scripts/scope-gate.sh` 헤더 주석이다.
- **저장소 밖 cwd (2026-09-08 사용자 결정)**: cwd 가 git 저장소 안이 아니면 Write·Edit 를 전부 막는다. 저장소가 없으면 «어디까지가 이 작업의 범위인가»를 판정할 기준 자체가 없어서다. 열어 두는 길은 두 가지뿐이다. 하나는 위의 memory 메타 예외이고, 다른 하나는 허용 목록 파일이다.
- **허용 목록 `~/.claude/config/scope-allow.txt`**: 한 줄에 절대 경로 접두 하나를 적고, 세션 cwd 가 git 저장소 밖일 때 그 아래는 쓰기가 허용된다(cwd 가 저장소 안이면 이 목록은 읽히지 않는다). `#` 로 시작하는 줄은 주석이며 `~` 를 홈으로 푼다. **이 파일은 사용자만 편집한다**(Claude 가 스스로 경계를 넓히면 게이트가 무의미해진다). 저장소 밖 경로에 써야 하면 파일을 고치지 말고 사용자에게 추가를 요청한다. 서버마다 다른 경로는 gitignore 된 `config/scope-allow.local.txt`(같은 형식)에 그 서버에서만 적고, 게이트는 두 파일을 합쳐 읽는다(2026-10-02 사용자 결정).
- **실사고 2026-09-07**: 한 프로젝트 세션의 coder 가 다른 프로젝트 저장소의 3파일 수정·1파일 추가, 사용자 지시로 전량 원복(저장소 이름과 원문 위치: `knowledge/harness/rules-project-server-history-2026-11-10.md` § code-execution-detail).

## § 코드 저장 규칙

### 임시 코드
- 탐색 / 검증 / 테스트 / 중간 단계 목적의 코드
- **자리 (MANDATORY, 2026-09-08 사용자 결정 · 2026-10-30 서버별 지정 추가)**: 서버 지정 파일 `~/.claude/config/scratch-root` 가 있으면 `<지정>/<프로젝트 이름>/<세션·잡 id>/` 를 쓰고 없거나 비면 종전 `<현재 프로젝트>/.scratch/<세션·잡 id>/`. 세션마다 폴더를 나눠 배경 작업이 여럿일 때 섞이지 않게 한다. 프로젝트 `.gitignore` 에 `.scratch/*` + `!.scratch/README.md` 를 두고, 폴더 안내는 `.scratch/README.md` 에 남긴다.
- **지정 파일 규칙 (2026-10-30)**: 사용자 결정: 임시 폴더는 사용자가 지정한 폴더 하위로 두고 기본값은 각 프로젝트 경로 하위다. 서버마다 지정한 값은 `config/scratch-root` 에 둔다(사용자 원문: `knowledge/harness/rules-project-server-history-2026-11-10.md` § code-execution-detail). 의뢰서 `intent/2026-10-30-scratch-root-per-server.md`.
  - 지정 파일은 한 줄 절대 경로이며 사용자가 정하는 값이다(세션은 사용자 지시로만 쓴다). git 이 무시한다(`.gitignore`).
  - 프로젝트 이름은 `git rev-parse --show-toplevel` 의 마지막 이름이다(하네스는 `.claude`).
  - 지정 폴더가 저장소 밖이면 `scope-gate.sh` 가 Write·Edit 를 막으므로 사용자가 `config/scope-allow.txt` 에 같은 경로를 넣어야 한다. scope-gate 는 지정 파일을 읽지 않는다(세션이 쓸 수 있는 설정이 쓰기 경계를 넓히면 안 되므로).
  - 이미 프로젝트 `.scratch/` 에 있는 파일은 옮기지 않는다.
  - 셸에서 자리 구하기: `R=$(cat ~/.claude/config/scratch-root 2>/dev/null); D=${R:+$R/$(basename "$(git rev-parse --show-toplevel)")}; D=${D:-$(git rev-parse --show-toplevel)/.scratch}/<세션 id>`
- **하네스 세션 작업 폴더에 쓰지 않는다**: `~/.claude/jobs/<잡>/tmp/` 와 `outputs/_scratch/` 에는 쓰지 않는다(전자는 경계 훅이 막고 후자는 읽기 차단이라 되읽지 못한다).
- **사용자 지정이 있으면 그것이 우선**. 지정도 없고 프로젝트도 못 정하겠으면 그때 질문한다.
- **승격**: 다시 쓸 값어치가 생기면 `scripts/`(재실행 파이프라인) 또는 `docs/error_analysis/<주제>/`(분석 산출물)로 옮긴다. 나머지는 `.scratch/` 에 둔다.
- **정리**: 1) 세션 종료 시 그 세션 폴더 삭제 여부를 사용자에게 확인 2) 30일 지난 폴더는 프로젝트에 `scripts/scratch_cleanup.py` 가 있으면 그것으로, 없으면 필요 시 직접 작성(하네스는 제공하지 않음)해 정리(기본 미리보기, `--apply` 로 삭제).

### 최종 코드
- 산출물로 보존되어야 하는 코드 (재실행 가능한 파이프라인)
- **지정된 목표 폴더**에 저장
- **폴더 미지정 시**: 작업 전 사용자에게 목표 폴더 경로를 반드시 질문
- 파일명은 기능을 명확히 표현 (예: `dicom_stats.py`, `stratified_split.py`)
- 단일 파일로 재실행 가능하도록 작성 (인자 없이 바로 실행 가능)

## § 폴더 사전 지정 (재질문 금지 조건)

대화 맥락에서 이미 명시된 경우 재질문하지 않는다:
- 임시 폴더: `config/scratch-root` 지정 폴더 또는 `<현재 프로젝트>/.scratch/<세션 id>/` 가 정해져 있으므로 **질문하지 않는다**(2026-09-08, 2026-10-30). 대화에서 사용자 지정이 따로 있으면 그것이 우선.
- 목표 폴더: 작업 지시에서 명시된 경우

## § 명령 묶음 스크립트 (2026-11-10 사용자 지시)

> **사용자 원문**: «다음부턴 명령어 묶음 단위로 .sh 로 주도록 해». 계기: 한 세션이 GPU 리셋 절차를 코드펜스 명령 8단계로 냈고 사용자가 한 줄씩 복사해 실행했다.

- **적용**: 사용자에게 직접 실행을 부탁하는 명령이 2개 이상일 때(sudo · 시스템 설정 · 정리 · 복구 절차 등). 명령 1개와 `launch-set.sh launch` 한 줄짜리 학습 발사 명령서는 종전 형식 그대로다. 훅이 막은 명령을 main 이 대신 실행하려고 승인을 묻는 형식(`rules/code-execution.md` § Hook 차단 시 처리 규칙)은 이 절의 대상이 아니다.
- **저장 위치**: 임시 코드 규약의 스크래치 폴더(§ 코드 저장 규칙). 파일 이름은 하는 일을 드러낸다(예: `gpu4_reset_steps.sh`).
- **스크립트 구성**:
  1. 머리 주석에 목적과 단계 목록을 적는다.
  2. 출력을 화면과 로그 파일에 함께 남긴다(`tee`, 결과 회수용). 로그 경로를 끝에 출력한다.
  3. 비가역 단계(삭제 · 리셋 · 서비스 정지 등) 앞에서 확인을 묻는다.
  4. 중간에 실패해도 복구 단계(멈춘 서비스 재시작 등)는 실행되게 한다(`trap`).
  5. 비밀값을 스크립트에 적지 않는다.
- **사용자에게 주는 것**: `bash <경로>` 한 줄 · 단계 요약(번호 목록) · 로그 파일 경로. 스크립트를 만든 세션이 실행하지 않는다(실행 분리 원칙 그대로).
