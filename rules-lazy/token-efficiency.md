# 토큰 효율 규칙

> **로드 시점**: 모든 작업 시작 전 검색·읽기 전략 선택 시 (항상 적용)

## 파일 탐색 전략 (순서 준수)

1. **Glob** → 파일 위치 파악 (파일 전체 읽기 금지)
2. **Grep** → 필요 심볼/키 위치 특정 (`head_limit` 활용)
3. **Read with offset/limit** → 필요 섹션만 읽기
4. 전체 파일 읽기는 **100줄 이하** 파일에만 허용
5. 이미 읽은 파일은 동일 세션 내 재읽기 금지 → 이전 내용 재활용

## 도구 출력 최적화

| 도구 | 제한 방식 |
|------|-----------|
| Grep | `head_limit: 20` 이하, 더 필요 시 offset 페이지네이션 |
| Bash (긴 출력) | `\| head -30` 파이프 추가 |
| wandb / 학습 로그 | 전체 출력 금지 → 핵심 수치(loss, metric)만 추출 |
| Glob | 결과 50개 초과 시 패턴 좁혀서 재시도 |

## 메인 세션 컨텍스트 보호 (MANDATORY)

메인 세션의 컨텍스트에 대량 데이터가 로드되는 것을 방지한다.

### 메인 세션 직접 Read 제한
- **3개+ 파일** 읽기 필요 시: Haiku scout에 위임 → 요약만 수신
- 단일 파일 Read는 메인 세션 직접 허용 (offset/limit 사용 필수)
- 이미 읽은 파일 재읽기 금지 (기존 규칙 유지)

### 메인 세션 연속 탐색 제한
- **Glob/Grep 3회+** 연속 필요 시: Haiku scout에 위임
- 단발성 Glob/Grep 1~2회는 메인 세션 직접 허용

### 메인 세션 응답 코드 블록 제한
- **10줄+ 코드 블록**: 응답 텍스트에 포함 금지 → subagent가 Write 도구로 저장
- diff 요약, 변경 설명만 응답에 포함
- 예외: 사용자가 "코드 보여줘" 명시 요청 시

### 메인 세션 git 출력 제한
- `git diff` / `git log` 결과를 메인 세션 컨텍스트에 직접 로드 금지
- Sonnet gitops에 위임하여 요약만 수신
- 예외: `git status` (짧은 출력)는 메인 세션 직접 허용

### Subagent 반환값 적재 최소화 (MANDATORY)

Subagent spawn은 parent context를 상속하지 않으나, **반환값은 main 컨텍스트에 그대로 적재**되어 입력 토큰을 누적시킨다. 대량 반환을 허용하면 1M 영역 진입 속도가 급격히 빨라진다.

| 반환 유형 | 규칙 (이 표가 단일 정본, 2026-10-17 `agent-routing-mcp.md` 사본을 여기로 합침) |
|----------|------|
| 100자 이하 요약 | main 직접 적재 허용 (권장 기본값, 1500자는 상한) |
| 100자~1500자 | 임시 폴더(`rules/code-execution.md` § 코드 저장 규칙)에 `{agent}_{주제}.md` 저장 후 경로만 반환 |
| 1500자 초과 | 위와 동일 + 반환 거부(재시도 요청) |
| raw JSON / 로그 원문 | 복사 금지 — 핵심 수치·파일 경로·결론만 추출 |
| Write 없는 에이전트 (`agents/*.md` 의 tools 에 Write 가 없는 것: qa·reviewer·security·scout·searcher·planner·gitops·citation-verifier) | «100자 초과는 파일 경유» 를 할 수 없으므로 본문 반환 상한(1500자) 안에서 요약해 돌려준다. 저장이 필요하면 main 이 수신 후 저장 |

qa 의 검증 증거 보고(`agents/qa.md` 보고 형식의 명령 원문 · exit code · 출력 발췌)는 이 반환 상한의 예외이고 요약을 맨 앞에 둔다. 증거를 파일로 남길 때는 main 이 수신 후 저장한다.

쓰기 범위가 지정 산출물뿐인 에이전트(tutor 재료 폴더 4파일, paper-read 의 researcher 리뷰 산출물)도 임시 폴더 저장 대신 압축 반환하고 main 이 저장한다.

scout 가 실제로 연 경로가 필요하면 main 이 scout 완료 뒤 `python3 ~/.claude/scripts/scout_detail.py --transcript <세션 폴더>/subagents/agent-<id>.jsonl --out <세션 임시 폴더>/scout-detail` 를 돌리고 표준 출력 JSON(개수 · 경로)만 맥락에 둔다. 경로는 scout 의 보고가 아니라 실행 기록의 도구 호출 입력에서 뽑은 것이고(파일 내용은 담지 않음), Bash 호출은 «경로 미추출» 로 센다. 옆에 생기는 json 은 살균하지 않은 원문 경로라서 문자열 비교 · 집합 대조에만 쓰고, 맥락에 읽어 들이거나 그 경로로 파일을 열지 않는다(2026-11-09 에이전트 정리 2단계). Bash 검색 결과의 줄 맨 앞 `경로:줄:` 꼴만 «검색 결과에서 뽑은 위치(검증 안 됨)» 로 따로 더해졌고(결정 S2R, 2026-11-10) 파일이 실제로 있는지는 확인하지 않은 값이다.

효과: subagent 30~50회 호출 시 누적 반환 약 150K 가 약 30K 토큰으로 줄어 1M 세션의 200K Extra usage 경계를 피한다.

### Agent Spawn Prompt 가드레일 (MANDATORY)

모든 `Agent(subagent_type=..., prompt=...)` 호출 prompt 하단에 아래 3줄 자동 포함:

```
## 반환 형식 제약 (main 컨텍스트 보호)
- 전체 반환 1500자 이내
- 상세 데이터는 임시 폴더(`rules/code-execution.md` § 코드 저장 규칙)에 `{agent}_{주제}.md` 저장 후 경로만 반환
  (**Write 미보유 에이전트는 파일 저장 불가 → 요약을 상한 내로 압축해 직접 반환**(목록은 위 표); 초과 시 분할 반환, 저장이 필요하면 main이 수신 후 저장)
- raw JSON/로그 원문 복사 금지, 요약만
```

### 대량 반환 도구 기본 limit 강제

| 도구 | 기본 limit | 초과 허용 조건 |
|------|---------|-------------|
| `mcp__mem0__get_memories` | limit=10 + filter 필수 | 사용자 명시적 "전체 조회" 요청 |
| `mcp__mem0__search_memories` | limit=5 | 작업 유형별 프로파일(§1.4)이 limit≥5 권장하는 경우만 |
| `mcp__tavily__tavily_search` | max_results=5 | V02/V05 SOTA·학술 검색 시 10까지 |
| Bash 명령 출력 | `\| head -30` 파이프 기본 | 사용자가 전체 출력 요청 시 |

## 응답 출력 토큰 절약 (MANDATORY — 긴 코드 생성 시)

### 코드 블록 기준 통합표 (주체별 — 혼동 방지)

| 주체·상황 | 기준 | 초과 시 |
|----------|------|--------|
| main 응답 텍스트 내 코드 블록 | **10줄** | subagent Write로 파일 저장 (§ 메인 세션 응답 코드 블록 제한) |
| 파일로 저장하는 코드 (coder 등) | **100줄** | 예외 없이 Write 도구 (응답 텍스트 포함 금지) |
| TikZ/matplotlib/LaTeX 스크립트 | 길이 무관 | 항상 Write 도구 |

### 긴 코드는 Write 도구로 파일에 직접 저장
- **100줄 이상 코드**: 응답 텍스트에 코드 블록 포함 **금지** → Write 도구로 파일 저장 후 경로만 보고
- **TikZ / matplotlib 스크립트**: 예외 없이 Write 도구 사용 (200~400줄 이상으로 출력 토큰 초과 위험)
- **응답 텍스트에 기술할 내용**: 파일 경로, 설계 결정, 실행 명령서 **만** (코드 전체 불가)

```
# ✅ 올바른 패턴 (경로는 {name} 플레이스홀더 — ci-gate 포인터 검사가 예시를 실참조로 오인하지 않게)
Write 도구로 docs/paper/scripts/gen_{name}_tikz.py 저장
→ 응답: "파일 저장 완료: docs/paper/scripts/gen_{name}_tikz.py / 실행: uv run python ..."

# ❌ 금지 패턴
응답 텍스트에 200줄짜리 TikZ 코드 블록 직접 출력
```

### 긴 출력 생성 전 컨텍스트 사전 점검
- 긴 코드 생성(TikZ/스크립트/LaTeX) **시작 전**: 컨텍스트 50%+ 시 compact 먼저 수행
  - 사용자에게 알림: "컨텍스트가 N% 입니다. compact 후 진행하겠습니다."
  - compact 지시: `/compact 실험 config·수정 내역 보존, 도구 출력 요약`
- 응답 중간에 토큰 부족이 예상되는 경우 → 사전에 분할 계획 보고 후 진행

## § 내부 사고 언어 (2026-07-29 사용자 지시)

최종 보고가 1회로 정례화되면서(`rules/agent-routing.md` § 프롬프트 1회) 사고 과정은 사용자에게 노출되지 않는다 — 따라서 **내부 사고의 언어·표현은 효율 기준으로 자유 선택**한다.

- **영어 등 더 토큰 효율적인 언어로 생각해도 된다** (동일 내용 기준 한글 대비 토큰 상당 절약) — 특히 더 고차원적·정밀한 추론이 가능한 방식이면 그쪽을 택한다. 수식·기호·의사코드 사고도 허용.
- **조건**: 내용·정확성을 해치지 않을 것. 한국어 고유 맥락(사용자 인용 원문·용어 뉘앙스·한글 룰 문구 대조)은 원문 그대로 다룬다 — 번역 왕복으로 뜻이 뭉개질 정보는 한글로 사고.
- **내부 산출물**(에이전트 spawn prompt·중간 메모·자기 검증 노트)도 동일 원칙 허용. 단 **사용자 대면 산출**(최종 보고·질문·문서·룰 본문)은 항상 한글(CLAUDE.md 기본 원칙 1).
- visible thinking 인터페이스에서도 동일 — 사고는 효율, 보고는 한글.
- 사용자 대면 한글에는 최종 보고와 진행 한 줄도 예외 없이 든다(2026-09-30 사용자 재지시, 날짜는 2026-11-10 상시 원칙 1에서 이관).
