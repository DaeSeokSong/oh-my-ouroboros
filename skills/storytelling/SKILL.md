# /storytelling — 연구 서사 기법 (but/therefore 구조)

> **출처 각인 (MIT)**: artemnovitckii/content-skills의 storytelling을 한글 연구 서사 맥락으로 적응 (2026-07-15 도입 — 원문의 SNS 릴스·스크립트 맥락과 viral-hooks 위임 구조는 제거, 연구 기록·보고에 유효한 기법만 채택). 원 저작 MIT 라이선스.
> **하네스 정합**: `/confluence-research-record`의 "동기→결과→해석→후속 **서사 형식**"과 사용자 지시(2026-07-13) "시도별 [무엇을/어떻게/왜 → 결과 → 다음 시도] 순차 서술"의 실행 기법. **Direction(결말부터) 기법 = CLAUDE.md 결론 선행 원칙과 동일** — 충돌이 아니라 같은 원리의 서사 확장.

## 사용 주체 · 시점

- **main**: 결과 보고 — 특히 다단계 작업 경과(시도→실패→원인→재시도), 실험 서사, 감사·디버깅 여정 보고 (2026-07-15 사용자 지시로 공식화)
- **researcher**: 논문 인트로·초록·related work 서사, 실험 분석 해석 구간
- **docs**: Confluence 연구 기록 (동기→결과→해석→후속)
- 명시 트리거: "스토리로", "서사로 정리", 연구 기록·발표 스크립트 요청

## 기법

1. **The Dance (핵심)** — 사건 연결을 "그리고(and then)"가 아니라 **"그러나(but) / 따라서(therefore)"** 로 잇는다. 나열은 정보, 전환은 서사다.
   - 나열: "A를 실행했고, B가 나왔고, C를 했다"
   - 서사: "A를 실행했다. **그러나** B가 붕괴했다. **따라서** C로 원인을 격리했다"
2. **Direction (결말부터)** — 결론을 먼저 쓰고 서사를 역산한다 (= 결론 선행). 독자가 목적지를 알아야 여정이 읽힌다.
3. **Rhythm** — 문장 길이를 가변으로. 짧은 문장은 강조다. 긴 문장은 맥락을 싣는다.
4. **Tone** — 동료에게 설명하듯. 보고서 관용구("본 문서에서는") 대신 직접 서술.

## 가드레일 (원문 안전장치 계승 + 하네스 강화)

- **사실 창작 금지 (MANDATORY)**: 실제 근거 없는 사건·인과·감정을 서사를 위해 만들지 않는다. 서사는 **실제 일어난 인과의 배열**이지 각색이 아니다 — 완료 게이트(증거 기반 보고)와 동일 원리.
- **적용 경계**: 단순 질문·1~2문장 답·표 중심 결과 보고에는 미적용 (보고 스타일의 적용 경계와 동일). 수치·판정 배지 등 실험 결과 형식(`rules-lazy/experiment-result-explanation.md`)이 우선하는 구간에서는 표가 본체, 서사는 해석 절에만.
- 정확도 표시·한계 공개는 서사에 밀리지 않는다.
