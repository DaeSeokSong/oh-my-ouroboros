# /solve — 5단계 구조적 문제해결

> **목적**: 사용자의 열린 질문·기획 요청을 "범위 잡기 → 근거 수집 → 문제 풀기 → 검증 → 보고" 5단계로 처리해, 모호한 질문이 구체적 해답으로 끝나게 한다. 하네스에 이미 있는 조각들을 **질문 1건 단위로 직렬화**하는 스킬 — 새 메커니즘이 아니라 기존 룰의 실행 순서 고정이다.

## 자동 적용 (예외 — 2026-07-09 사용자 승인)

"스킬 자동 제안 = 제안 먼저" 원칙의 **명시적 예외**: 이 스킬은 외부 부작용(설치·쓰기·비용 게이트)이 없는 순수 방법론이므로, 트리거 감지 시 제안 없이 **바로 적용**한다. 적용 시 첫 줄에 `[/solve 5단계 적용]` 1줄 표시 (침묵 금지 — 사용자 통제 유지).

### 트리거 (자동 적용)
- 의견 요청: "어떻게 생각해?", "~하는 게 어때?", "뭐가 좋을까?", "괜찮을까?"
- 공동 기획: "같이 기획해보자", "설계해보자", "방향 잡아줘"
- 미지 영역 질문: 사용자가 모르는 개념·도구를 물으며 **채택/적용 판단**이 걸려 있을 때

### 생략 (over-application 가드)
- 단순 사실 질문 (1~2문장 답으로 끝남 — 예: "X가 뭐야?") → main 직접 답변
- 대상·방법이 명확한 실행 지시 → 일반 라우팅
- 라우팅 9(토론·검토·타당성 — /discuss)나 /research가 더 적합한 규모 → 해당 라우팅 우선 (이 스킬은 **단일 질문 스케일**)
- 이미 /solve 진행 중 (깊이 N=1)

## 0단계 — 질의 정리·확인 (MANDATORY, 무조건 선행 — 2026-07-15 사용자 교정)

> **판단 근거**: 종전에는 1단계 안의 "조건부 질문지 게이트"(4종 걸릴 때만 질문)였으나, "깨끗함" 자기판정이 관대해져 실제로는 즉답으로 흐르는 문제가 실측됨 (2026-07-15 사용자: "냅다 답변부터 한다"). 확인 행위 자체를 무조건화한다 — 질문 유무는 조건부, **재정리 제시와 사용자 확인은 무조건**.

답변·근거 수집을 시작하기 **전에** 반드시:

1. **질의 재정리 제시** — "이렇게 이해했습니다" 1~3줄: 진짜 묻는 것 / 답변 범위 / 성공 기준 후보.
2. **모호점 질문** (해당 시, **개수 제한 없음** — 답이 달라지는 모호점은 전부 질문하되 한 라운드에 묶어 제시, AskUserQuestion 활용, 각 문항에 추천안 포함): ⓐ 해석 분기(2+ 갈래) ⓑ 부족한 정보(답이 달라지는 미지 값 — 예산·환경·대상 범위) ⓒ 과잉 의심(요청에 있지만 없어야 목적에 맞아 보이는 부분 — 근거와 함께 제외 제안) ⓓ 성공 기준 미정(무엇이면 "해결됨"인가).
   - prompt-routing "재질문 최대 3개" 상한의 **명시적 예외** (2026-07-15 사용자 지시) — /solve 0단계에 한정, 일반 요청 구체화에는 기존 상한 유지.
3. **동의까지 수렴 루프** — 사용자 응답을 반영해 이해 요약을 **갱신 제시** → 남은/새로 드러난 모호점 재질문 → 사용자가 동의("맞다"·"그대로 진행")할 때까지 반복하며 질의를 구체화·고도화한다. 동의 후에만 1단계 진입. 루프 위생: 이전 라운드에서 확정된 사항 재질문 금지, 진전 없는 동일 질문 반복 금지 (라운드마다 요약이 실제로 좁혀져야 한다).
4. **4종이 모두 깨끗해도 생략 금지** — 재정리 + "이대로 진행할까요? 수정·추가할 부분 있으면 알려주세요" 확인은 항상 제시하고 **사용자 응답 후** 1단계 진입. 추측 진입 금지.

**예외** (적용 시 응답 첫머리에 1줄 명시): ⓐ 사용자가 "바로 답해"·"즉시" 명시 ⓑ 직전 턴에서 동일 질의를 이미 확인함(재확인 루프 금지) ⓒ 질문 불가한 무인 컨텍스트(헤드리스 등) — 채택 해석 명시 후 진행 ⓓ 사용자가 확인 단계를 거부한 이력 — 가장 합리적 해석 1줄 명시 후 진행 (prompt-routing 재질문 거부 처리와 동일).

## 메타프롬프트 모드 (실행 작업 한정 — 2026-07-21 사용자 승인)

> **진입 조건 (2026-07-23 확장 — 미발동 교정)**: ① /solve 트리거 건 중 **실행 작업**(코드·문서·실험 등 산출물 생성)이 포함된 경우 ② **prompt-routing Step 1 구체화 대상(모호)이면서 산출물 생성이 걸린 비자명 작업** (Step 1 핸드오프). ①만으로는 "의견 요청"과 "실행 작업"이 실전에서 거의 교집합이 없고 모호한 실행 요청은 Step 1이 선점해 **도달 불가 조건**이었다 — 신설 2일간 0회 발동 실측(구축-미사용 rot #5). 단순 의견·사실 질문은 기존 0~5단계만. **진입 시 첫 줄 `[메타프롬프트 모드]` 표시 (발동 가시화 — 미발동 감지 가능하게).**
> **판단 근거 (설계의 핵심)**: 반복의 심판은 모델 자신이 아니라 **사용자 승인** — 외부 피드백 없는 LLM 자기교정은 개선이 미미하거나 악화된다는 실증(Huang et al. 2024) 때문에 자기비평은 1회로 제한하고, 수렴 루프의 종료 판정은 사용자(=외부 피드백)가 한다. ④의 재실행 판정도 성공 기준 대비 실측이 근거다.

절차 (0단계 수렴 루프와 병합해 진행 — 별도 의식 아님):

1. **외부 교차검증 질문 (진입 시 1회)**: 연결된 외부 검증자(현재: Codex)가 있으면 "확정 전 프롬프트를 외부 AI와 교차검증할까요?" 질문 — 모델·effort 선택지는 `rules-lazy/codex-model-gate.md` 규약 재사용(중복 정의 금지). 외부 검증자 부재 시 질문 생략.
2. **ⓐ 프롬프트 초안** — main이 고정 포맷으로 작업 프롬프트를 명시 작성:
   ```
   [작업 프롬프트 vN]
   목표: (1줄)          맥락: (관련 파일·이력·현재 상태)
   제약: (금지·경계)     성공 기준: (검증 가능한 완료 조건)
   산출 형식: …         도구·출처: …
   ```
   (spawn prompt 4요소의 확장 — 실행 주체가 main이든 subagent든 동일 포맷. subagent 실행 시 이 프롬프트가 곧 spawn prompt가 된다)
3. **ⓑ 비평 1회 반영**: 자기비평 **1회 한정**(맹점·모호어·성공 기준 검증 가능성 점검) → 1에서 선택했으면 외부 AI 교차비평 반영. 자기비평 무한 반복 금지.
4. **ⓒ 사용자 수렴 루프**: 프롬프트 vN을 사용자에게 제시 — "이대로 실행할까요? 수정할 부분은?" → 수정 요청을 반영해 ⓐ~ⓒ 반복. **사용자가 "원하는 내용이 모두 담겼다"고 승인할 때까지** (횟수 무제한 — 0단계와 동일 루프 위생: 확정 사항 재질문 금지).
5. **ⓓ 실행·결과 루프**: 승인된 프롬프트로 실행 → 결과가 성공 기준과 어긋나면 어긋난 지점을 근거로 프롬프트 수정(사용자 확인) 후 재실행. 반복 실패 신호는 `rules-lazy/agent-eval.md`(T41)로 축적.

## 5단계 절차

| 단계 | 행동 | 기존 하네스 매핑 |
|------|------|----------------|
| **1. 범위 잡기** | 0단계에서 사용자와 확정한 내용을 결정 가능한 형태로 잠금: ① 진짜 묻는 것 1줄 ② 성공 기준·제약 확정 (질문지 게이트는 0단계로 이동·무조건화 — 2026-07-15) | prompt-routing Step 1 (구체화·다중 해석) |
| **2. 근거 수집** | 출처 3계열에서 필요한 것만: 내부(코드·파일 — scout/Grep), 이력(mem0 3축 — advisory), 외부(Tavily 단발/searcher — 최신성·수치·사실) | tavily-auto·mem0-auto §1.4·§1.5 |
| **3. 문제 풀기** | 대안 2~3개 + 각 트레이드오프 + **추천안 1개와 그 이유** — 단일안 강요 금지, 근거 없는 단정 금지 | prompt-routing 단순 대안 푸시백·brainstorming 흡수 원칙 |
| **4. 검증** | 추천안에 대한 **반증 시도** 1회: 근거 재대조(출처가 실제로 그 주장을 하는가), 수치 재계산, 현재 코드/문서와 충돌 확인. 필요 시 second-opinion(§6)·citation-verifier(논문) | 완료 게이트(CLAUDE.md 6)·verify 액면 수용 금지 |
| **5. 보고** | 보고 스타일 준수: ①동작원리 ②쉬운 설명 ③실생활 예시 + [Brief] + **정확도 표시**(높음/중간/낮음) + 검증에서 발견한 반례·한계 정직 공개 | answer-detail·보고 스타일 |

## 운영 규칙

- **단계 스킵**: 이미 충족된 단계는 건너뛰되 보고에 "(2단계: 대화 내 근거로 충분 — 외부 검색 생략)"처럼 1줄 명시. 5단계를 의식(ritual)이 아니라 체크리스트로 사용.
- **0단계에서 멈추는 경우**: 재정리·질문지를 낸 뒤에는 사용자 응답 대기 — 추측으로 다음 단계 진입 금지 (prompt-routing 추측 실행 금지와 동일). 사용자가 "알아서 해"로 거부하면 가장 합리적 해석 1줄 명시 후 진행(가정 표기).
- **깊이 제한 N=1**: 이 스킬 실행 중 다른 스킬 재귀 호출 금지 (순차 호출 허용 — 예: 보고 후 사용자가 /discuss 선택).
- **토큰 가드**: 2단계 외부 검색은 Tavily 단발 1~2회 상한 (광범위 필요 시 searcher 위임 또는 /research 재라우팅 제안).
