# /solve — 5단계 구조적 문제해결

> **목적**: 사용자의 열린 질문·기획 요청을 "범위 잡기 → 근거 수집 → 문제 풀기 → 검증 → 보고" 5단계로 처리해, 모호한 질문이 구체적 해답으로 끝나게 한다. 하네스에 이미 있는 조각들을 **질문 1건 단위로 직렬화**하는 스킬 — 새 메커니즘이 아니라 기존 룰의 실행 순서 고정이다.

## 자동 적용 (예외 — 2026-07-09 사용자 승인)

"스킬 자동 제안 = 제안 먼저" 원칙의 **명시적 예외**: 이 스킬은 외부 부작용(설치·쓰기·비용 게이트)이 없는 순수 방법론이므로, 트리거 감지 시 제안 없이 **바로 적용**한다. 적용 시 첫 줄에 `[/solve 5단계 적용]` 1줄 표시 (침묵 금지 — 사용자 통제 유지).

### 트리거 (자동 적용)
- 의견 요청: "어떻게 생각해?", "~하는 게 어때?", "뭐가 좋을까?", "괜찮을까?"
- 공동 기획: "같이 기획해보자", "설계해보자", "방향 잡아줘"
- 미지 영역 질문: 사용자가 모르는 개념·도구를 물으며 **채택/적용 판단**이 걸려 있을 때

### 생략 (over-application 가드)
- 단순 사실 질문 (1~2문장 답으로 끝남 — 예: "X가 뭐야?") → main 직접 답변
- 대상·방법이 명확한 실행 지시 → 일반 라우팅
- 라우팅 9(토론·검토·타당성 — /discuss)나 /research가 더 적합한 규모 → 해당 라우팅 우선 (이 스킬은 **단일 질문 스케일**)
- 이미 /solve 진행 중 (깊이 N=1)

### "?" 질문 → 사용 여부 제안 (2026-08-06 사용자 지시)
자동 적용·생략 어느 쪽에도 확실히 안 걸리는 질문 포함, 사용자 발화에 **"?"가 있으면** 즉답(또는 일반 처리)과 함께 말미에 1줄 제안: "이 질문을 /solve(그릴링 핑퐁)로 깊게 팔까요?" — 자동 적용이 아니라 **제안**이며, 단순 사실 1문1답도 즉답을 먼저 준 뒤 제안만 붙인다(답변 지연 금지).

## 0단계 — 질의 정리·확인 (MANDATORY, 무조건 선행 — 2026-07-15 사용자 교정)

> **판단 근거**: 종전에는 1단계 안의 "조건부 질문지 게이트"(4종 걸릴 때만 질문)였으나, "깨끗함" 자기판정이 관대해져 실제로는 즉답으로 흐르는 문제가 실측됨 (2026-07-15 사용자: "냅다 답변부터 한다"). 확인 행위 자체를 무조건화한다 — 질문 유무는 조건부, **재정리 제시와 사용자 확인은 무조건**.

답변·근거 수집을 시작하기 **전에** 반드시:

1. **질의 재정리 제시** — "이렇게 이해했습니다" 1~3줄: 진짜 묻는 것 / 답변 범위 / 성공 기준 후보.
2. **모호점 제시** (해당 시, **개수 제한 없음** — 답이 달라지는 모호점은 전부 드러내되 한 라운드에 묶어 제시): 1) 해석 분기(2+ 갈래) 2) 부족한 정보(답이 달라지는 미지 값 — 예산·환경·대상 범위) 3) 과잉 의심(요청에 있지만 없어야 목적에 맞아 보이는 부분 — 근거와 함께 지적) 4) 성공 기준 미정(무엇이면 "해결됨"인가).
   - ★**추천·유도 금지, 선택지는 표로 (2026-08-07 사용자 지시, 2026-09-15 개정)**★ 각 모호점에 **한 줄 이력**(언제/무엇을/어떻게/왜 진행했는지, 없으면 "없음")과 **한 줄 결론**(그 결과가 확정한 것)을 머리에 두고, 그 아래 **선택지 2~4개·장단점 표·비교 표**를 싣는다(형식 정본: `answer-detail.md` § 문제·선택지 보고 형식). 추천안·`(Recommended)`·유도 배치는 금지. 되묻기 축은 `rules-lazy/decision-sovereignty.md`가 정본.
   - prompt-routing "재질문 최대 3개" 상한의 **명시적 예외** (2026-07-15 사용자 지시) — /solve 0단계에 한정, 일반 요청 구체화에는 기존 상한 유지.
   - 메타프롬프트 모드의 인터뷰 모드에서는 묶어 제시하지 않고 한 번에 한 질문씩 묻는다(아래 § 인터뷰 모드).
3. **동의까지 수렴 루프 (의도 확인 3단)**: 사용자 응답을 반영해 이해 요약을 **갱신 제시**하고 남은 모호점과 새로 드러난 모호점을 다시 묻는다. 모호점이 닫히면 아래 3단으로 끝내며 3단을 마친 뒤에만 1단계에 들어간다. 루프 위생: 이전 라운드에서 확정된 사항 재질문 금지, 진전 없는 동일 질문 반복 금지 (라운드마다 요약이 실제로 좁혀져야 한다).
   1) **되읽기**: 의도를 한 문장으로 되읽는다.
   2) **명시적 확인**: 사용자가 그 문장이 맞다고 답해야 확인이다(«맞다» · «그대로 진행»). 침묵 · 다른 화제의 답 · 무엇에 대한 것인지 불분명한 «응» 은 확인으로 치지 않고 같은 문장을 다시 묻는다.
   3) **프로브 질문 1회**: «이 이해가 틀렸다면 어디가 가장 틀렸겠습니까» 꼴로 틀린 곳을 찾게 하는 질문을 한 번 던진다(추천 · 유도 금지). 고칠 곳이 나오면 1)로 돌아가고 없다고 답하면 1단계에 들어간다.
4. **4종이 모두 깨끗해도 생략 금지** — 재정리 + "이대로 진행할까요? 수정·추가할 부분 있으면 알려주세요" 확인은 항상 제시하고 **사용자 응답 후** 1단계 진입. 추측 진입 금지.

**예외** (적용 시 응답 첫머리에 1줄 명시): 1) 사용자가 "바로 답해"·"즉시" 명시 2) 직전 턴에서 동일 질의를 이미 확인함(재확인 루프 금지) 3) 질문 불가한 무인 컨텍스트(헤드리스 등) — 채택 해석 명시 후 진행 4) 사용자가 확인 단계를 거부한 이력 — 가장 합리적 해석 1줄 명시 후 진행 (prompt-routing 재질문 거부 처리와 동일, 바꾸는 요청이면 그 1줄을 계획으로 올려 확정받은 뒤 진행: CLAUDE.md 원칙 3).

## 그릴링 핑퐁 루프 (0~5단계 관통 — 2026-08-06 사용자 지시. 출처: mattpocock/skills `grilling`(MIT) 이식+확장)

> **목적**: 사용자 질문을 1회 답변으로 끝내지 않고, 꼬리에 꼬리를 무는 브레인스토밍 핑퐁으로 **사용자의 의문이 실제로 해소될 때까지** 진행한다. 0단계 수렴 루프가 "질의 이해"의 수렴이라면 이 루프는 "답변·의문 해소"의 수렴 — 5단계 보고 이후에도 이어진다.

### 질문 트리 운영 (design tree + frontier)
- 논의 지형을 **질문 트리**로 관리한다: 각 결정에서 파생되는 하위 결정이 가지.
- 한 라운드에는 **frontier**만 낸다 — 선행 조건이 이미 확정돼 **지금 추측 없이 물을 수 있는** 질문. 답이 이번 라운드의 다른 미해결 질문에 의존하면 다음 라운드로 미룬다(원문: "belongs to a later round").
- **라운드당 되묻기는 1~2문항** — 질문지를 쏟아내면 다시 "평가"가 된다. 되묻기의 축(경계/대안생성/측정/비용/전제/범위)·유도 질문 금지·사실 동봉은 `rules-lazy/decision-sovereignty.md` 규칙 2가 정본(중복 정의 금지). 층위 구분: 0단계의 모호점 **드러내기**는 무제한(한 라운드에 묶어 제시), 결정을 고도화하는 **되묻기**가 1~2문항이다.
- ★**추천 답 금지, 선택지는 표로 (2026-08-07 사용자 지시로 교체, 2026-09-15 개정)**★ 종전에는 모든 질문에 추천 답(➡️)을
  붙였다. 추천을 붙이면 사용자가 **평가자** 위치가 되어 모델이 놓친 축은 시야에 들어오지
  않는다. 이제는 **한 줄 이력 + 한 줄 결론**을 머리에 두고 **선택지 2~4개·장단점·비교 표**(정본: `answer-detail.md` § 문제·선택지 보고 형식)를 붙인다.
  백지 질문 금지의 취지(판단 재료 제공)는 이력·결론·선택지 표가 대신한다. `rules-lazy/decision-sovereignty.md` 규칙 1.
- **사실 확인은 에이전트 몫, 사용자 몫이 아니다**(원문: "Finding facts is your job, never the user's."): 코드·문서·검색으로 답이 나오는 사실 질문은 2단계 도구로 직접 조사하고, 사용자에게는 **판단 질문만** 남긴다.

### 종료 조건 (둘 다 충족해야 종료)
1. **frontier 소진**: 트리의 전 분기 방문 + 암묵 가정 0.
2. **사용자 확인 (MANDATORY)**: "의문이 해소되셨나요? 더 파고들 부분이 있나요?"를 명시적으로 묻고, 사용자가 **해소됐다고 답할 때까지** 핑퐁을 계속한다. frontier가 비어도 이 확인 없이 종료 금지.

### 비굴종 동의 (MANDATORY — 무조건 동의 금지)
사용자 주장에 대한 응답은 아래 3형 중 하나여야 한다 (CLAUDE.md 원칙 7 "일관된 주장"의 이 스킬 내 구체화):
- **동의**: 확실하고 객관적인 근거가 있을 때만 — 근거를 함께 제시한다.
- **수용+결함 명시**: 사용자 주장이 강력하면 결함이 있어도 받아들이되, **무슨 결함이 있는지 반드시 알린 뒤** 수용한다.
- **반박 유지**: 위 둘에 해당하지 않으면 근거를 들어 반박하고 토론을 계속한다.

## 메타프롬프트 모드 (실행 작업 한정 — 2026-07-21 사용자 승인)

> **진입 조건 (2026-07-23 확장 — 미발동 교정)**: 1) /solve 트리거 건 중 **실행 작업**(코드·문서·실험 등 산출물 생성)이 포함된 경우 2) **prompt-routing Step 1 구체화 대상(모호)이면서 산출물 생성이 걸린 비자명 작업** (Step 1 핸드오프). 1) 만으로는 "의견 요청"과 "실행 작업"이 실전에서 거의 교집합이 없고 모호한 실행 요청은 Step 1이 선점해 **도달 불가 조건**이었다 — 신설 2일간 0회 발동 실측(구축-미사용 rot #5). 단순 의견·사실 질문은 기존 0~5단계만. **진입 시 첫 줄 `[메타프롬프트 모드]` 표시 (발동 가시화 — 미발동 감지 가능하게).**
> **판단 근거 (설계의 핵심)**: 반복의 심판은 모델 자신이 아니라 **사용자 승인** — 외부 피드백 없는 LLM 자기교정은 개선이 미미하거나 악화된다는 실증(Huang et al. 2024) 때문에 자기비평은 1회로 제한하고, 수렴 루프의 종료 판정은 사용자(=외부 피드백)가 한다. 4) 의 재실행 판정도 성공 기준 대비 실측이 근거다.

절차 (0단계 수렴 루프와 병합해 진행 — 별도 의식 아님):

1. **외부 교차검증 질문 (진입 시 1회)**: 연결된 외부 검증자(현재: 상시 Grok, Codex 는 사용자가 명시 허용한 건만)가 있으면 "확정 전 프롬프트를 외부 AI와 교차검증할까요?" 질문 — 모델·effort 선택지는 `rules-lazy/codex-model-gate.md` 규약 재사용(중복 정의 금지). 외부 검증자 부재 시 질문 생략.
2. **1) 프롬프트 초안** — main이 고정 포맷으로 작업 프롬프트를 명시 작성:
   ```
   [작업 프롬프트 vN]
   목표: (1줄)          맥락: (관련 파일·이력·현재 상태)
   제약: (금지·경계)     성공 기준: (검증 가능한 완료 조건)
   산출 형식: …         도구·출처: …
   원문: (사용자 지시 인용 또는 원문 파일 경로)
   ```
   (spawn prompt 5요소의 확장이다. 다섯째 요소는 사용자 지시 원문 인용 또는 원문 파일 경로이고 정본은 `rules-lazy/agent-routing-mcp.md` 다. 실행 주체가 main이든 subagent든 동일 포맷이며 subagent 실행 시 이 프롬프트가 곧 spawn prompt가 된다)
3. **2) 비평 1회 반영**: 자기비평 **1회 한정**(맹점·모호어·성공 기준 검증 가능성 점검) → 1에서 선택했으면 외부 AI 교차비평 반영. 자기비평 무한 반복 금지.
4. **3) 사용자 수렴 루프**: 프롬프트 vN을 사용자에게 제시 — "이대로 실행할까요? 수정할 부분은?" → 수정 요청을 반영해 1)에서 3)까지 반복. **사용자가 "원하는 내용이 모두 담겼다"고 승인할 때까지** (횟수 무제한 — 0단계와 동일 루프 위생: 확정 사항 재질문 금지).
5. **4) 실행·결과 루프**: 승인된 프롬프트를 먼저 **intent.md 로 저장·커밋**한다(비자명 실행 작업이면 필수, `skills/intent/SKILL.md` — 채팅의 [작업 프롬프트 vN]은 요약본이고 파일이 정본, 2026-09-06 사용자 지시). 그 뒤 실행 → 결과가 성공 기준과 어긋나면 어긋난 지점을 근거로 프롬프트 수정(사용자 확인) 후 재실행. 반복 실패 신호는 `rules-lazy/agent-eval.md`(T41)로 축적.

### 인터뷰 모드 (모호한 비자명 작업, 2026-11-24 사용자 결정)

- **발동**: 진입 조건 2)일 때만 쓴다(prompt-routing Step 1 모호 패턴에 걸린 비자명 작업). 명확한 실행 지시 · 사실 질문 · 예약 실행 · «알아서 해» 로 구체화를 거부한 뒤에는 쓰지 않는다.
- **한 번에 한 질문**: 한 턴에 질문 하나만 내고 답을 받은 뒤 다음 질문으로 간다. 0단계의 «한 라운드에 묶어 제시» 와 prompt-routing 의 «최대 3개 한 번에» 를 이 모드에서는 이것으로 대신한다.
- **추측 답 · 추천 금지**: 질문에 모델의 추측 답이나 추천을 붙이지 않는다(원칙 7.5, `rules-lazy/decision-sovereignty.md`).
- **사실은 묻지 않는다**: 코드 · 문서 · 검색으로 답이 나오는 것은 먼저 조사하고 판단 질문만 남긴다.
- **질문 도구**: 열린 질문은 글로 하나를 묻는다. 고르는 질문은 결정 팝업 한 항목으로 묻고 모바일 모드가 켜져 있으면 AskUserQuestion 한 항목으로 묻는다.
- **질문 형식**: 열린 질문은 선택지 표 없이 글로만 묻는다. 고르는 질문은 0단계 2번의 선택지 표 규칙(한 줄 이력 · 한 줄 결론 · 선택지 2~4개, 추천 없음)을 그대로 따른다.
- **상한**: 질문이 5개를 넘으면 다음 질문 전에 «계속 · 이대로 진행» 을 묻는다. «이대로 진행» 이면 질문을 멈추고 수렴으로 간다.
- **수렴**: 질문이 끝나면 0단계 3번의 의도 확인 3단(되읽기 → 명시적 확인 → 프로브 질문 1회)으로 닫고 위 절차 2번(«1) 프롬프트 초안»)으로 넘어간다.
- **출처**: 절차의 착안은 공개 스킬 interview-me(addyosmani/agent-skills, MIT)다. 원문을 복사하지 않고 이 하네스의 결정 주권 규칙에 맞게 다시 썼으며 질문마다 추측 답을 붙이는 방식은 넣지 않았다(2026-11-24 사용자 결정).

## 운영 규칙

- **단계 스킵**: 이미 충족된 단계는 건너뛰되 보고에 "(2단계: 대화 내 근거로 충분 — 외부 검색 생략)"처럼 1줄 명시. 5단계를 의식(ritual)이 아니라 체크리스트로 사용.
- **0단계에서 멈추는 경우**: 재정리·질문지를 낸 뒤에는 사용자 응답 대기 — 추측으로 다음 단계 진입 금지 (prompt-routing 추측 실행 금지와 동일). 사용자가 "알아서 해"로 거부하면 가장 합리적 해석 1줄 명시 후 진행(가정 표기). 바꾸는 요청이면 그 1줄을 계획으로 올려 확정받은 뒤 진행한다(CLAUDE.md 원칙 3).
- **깊이 제한 N=1**: 이 스킬 실행 중 다른 스킬 재귀 호출 금지 (순차 호출 허용 — 예: 보고 후 사용자가 /discuss 선택).
- **토큰 가드**: 2단계 외부 검색은 Tavily 단발 1~2회 상한 (광범위 필요 시 searcher 위임 또는 /research 재라우팅 제안).
