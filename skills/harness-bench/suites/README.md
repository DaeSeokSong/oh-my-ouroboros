# 벤치 문제지 보관소

벤치에 쓰는 문제지와 정답표를 파일로 둔다. 2026-10-01 의 첫 문제지(18문항)는 대화 안에만 있었고 잡 임시 폴더가 비워지면서 사라져, 2026-11-12 에 세션 기록에서 복구해야 했다. 같은 일을 막으려고 여기에 고정본을 둔다.

## rules-v2 (2026-11-12 고정, 24문항)

- `rules-v2/questions.md`: 응답자에게 주는 문제지. 상시 규칙(`CLAUDE.md` + `rules/*.md`)만 읽고 «규칙상 해야 하는 행동»을 답하게 한다.
- `rules-v2/key.md`: 채점자 전용 정답표와 채점 규칙. 응답자에게 보여 주지 않는다.
- 1~18번은 2026-10-01 고정본(벤치 audit-1001)과 같은 문항이다. 1번의 정답도 고정본 그대로다(2026-11-12 결정: push · pull 은 사용자만, 승인 표시가 있어도 훅이 막는다). 19~24번은 그 뒤에 생기거나 바뀐 규칙을 묻는다.

## 재는 법

1. 응답: 서로 독립된 haiku scout 를 사이클 수만큼 소집한다. 지시문에는 문제지 전문과 «상시 규칙 6파일을 전부 읽고, 그 밖의 파일은 읽지 않는다»를 넣는다. 정답표 경로는 알려 주지 않는다. 이 문제지가 재는 범위는 상시 규칙이고 lazy 규칙·스킬 변경의 효과는 재지 못한다. 채점 전에 응답자 기록(transcript)의 Read 경로가 상시 규칙 6파일뿐인지 확인하고, 다른 파일(특히 `suites/` 아래)을 읽은 응답은 버리고 다시 잰다.
2. 채점: 응답 작성과 규칙 수정에 관여하지 않은 qa 가 정답표로 이진 채점한다. main 은 채점하지 않는다.
3. 지표: `attempts`=1, `interventions`=`모호:` 로 시작한 답의 수, `qa_fail`=오답 수.
4. 기록: 사이클마다 근거 파일(`qa-report*.md`, `$HOME` 아래. 잡 폴더에는 쓸 수 없다)을 하나 쓰고 바로 `harness-bench.sh before|after` 로 기록하기를 차례로 한다. 근거 파일을 한꺼번에 써 두면 스크립트가 기록을 거부한다. After 근거 파일에는 `무관작업개재=Y` 를 적는다.
5. 판정: Before · After 가 각각 3사이클 이상일 때 `harness-bench.sh gate <벤치 ID>`. 한 지표라도 나빠지면 FAIL 이다.

## 문제지를 바꿀 때

문항이나 정답을 바꾸면 전후 비교가 깨진다. 고칠 때는 새 폴더(`rules-v3/`)와 새 벤치 ID 로 기준 측정부터 다시 한다. 정답이 규칙 변경으로 달라진 문항은 무엇이 왜 달라졌는지 `key.md` 머리에 적는다.
