# 모델 배정 통합 규칙

> **로드 시점**: 작업 시작 전 subagent 모델 결정 시 (항상 적용)
> **전제**: 메인 세션 = 최상위 가용 모델 (예: Fable 5 / Opus 4.8 — 머신별 pin: gitignored settings.local.json 또는 ANTHROPIC_MODEL env. 추적 settings.json에는 model 키를 두지 않음, 2026-07-15). subagent 모델은 별칭(opus/sonnet/haiku)으로 최신 자동 추적 — 특정 버전 하드코딩 금지.
> **핵심 원칙**: 메인 직접 처리 조건에 해당하지 않는 모든 작업은 반드시 적합 모델의 subagent에 위임한다. (아래 "Opus"=메인 세션 모델 지칭. planner·researcher는 opus 동급 subagent — "하위 모델"이 아니라 **분리 컨텍스트 위임**이 목적)
> **second-opinion (opt-in)**: §1 고위험 결정(아키텍처·수식)은 사용자 명시 요청 시 Sonnet 독립 검토 1회 교차검증 — 상세: `rules-lazy/model-assignment-rules.md` §6
> **판단 시점**: `prompt-routing.md` Step 1.5에서 매 작업 실행 전 강제 판단

## 1. Opus 메인 직접 처리 조건

아래 중 하나라도 해당하면 메인 세션(Opus)이 직접 처리한다. subagent 위임 금지:

| 조건 | 기준 |
|------|------|
| 수식·알고리즘 구현 | 수학 수식 포함 코드 |
| 도메인 타당성 검증 | domain-specific 메커니즘 판단 포함 |
| 아키텍처 설계·변경 | 모듈 간 인터페이스 변경 포함 |
| 복합 디버깅 | 인과관계 분석 + 로직 수정이 묶인 경우 |
| 사용자 합의 필요 | "검토"/"설계"/"타당성"/"비교" 키워드 포함 |
| 크로스 모듈 영향 | 수정 파일 ≥ 3개 + 모듈 간 의존성 변경 수반 |

→ 미해당 시: §2~§3 조건에 따라 subagent 위임

> **아키텍처 소유권 (라우팅 5와의 관계)**: 설계안 작성·대안 비교는 planner에 위임 가능(자문) — **최종 아키텍처 결정·사용자 합의는 main 소유**. "Opus 직접 처리"는 결정·합의를 뜻하며 planner 자문 위임과 상충하지 않는다.
> **researcher·토론 소유권 (라우팅 6·9와의 관계)**: 실험 분석·논문 본문·설계 비판 평가는 researcher에 위임 가능(자문·초안), "검토·타당성·비교" 토론은 라우팅 9의 teammate 소집으로 진행 — 두 경우 모두 **최종 판단·사용자 합의는 main 소유** (planner 각주와 동일 원리). §1의 "사용자 합의 필요" 행은 합의 단계의 직접 수행을 뜻하며 자문·토론 위임과 상충하지 않는다.

### Whole-Job 예외 (과분해 견제)

**결합도 높은 다단계 작업**(단계 간 공유 컨텍스트가 크고 인수인계 비용이 모델 단가 차를 상회)은 단계별로 쪼개 위임하지 않고 **한 에이전트가 전체를 완주**한다 — main 직접 또는 적합 최고 모델 subagent 1개. parallel-dispatch 가능한 독립 작업엔 적용 금지(기준=단계 간 결합도), 위임 보고에 "whole-job: {결합 근거 1줄}" 명시. 판단 신호·근거 상세: `rules-lazy/model-assignment-rules.md` §7.

## 2. Sonnet subagent 위임 조건

아래 조건에 해당하면 Sonnet subagent에 위임한다:

| 카테고리 | 구체적 조건 | 예시 |
|----------|-----------|------|
| **코드 구현** | 새 함수·클래스 작성 | 새 모델 레이어 추가 |
| **코드 수정** | 기존 함수 로직 변경 (단일 모듈 내) | loss function 수정 |
| **버그 수정** | 원인 파악 완료 후 단일 지점 수정 | off-by-one, 타입 불일치 |
| **코드 분석** | 단순 탐색 이상의 구조 파악 | 의존성 그래프 추적 |
| **모듈 추가** | 신규 파일 생성 (로직 설계는 Opus) | 헬퍼 함수 파일 생성 |
| **설정 파일 수정** | rules/skills/agents .md 파일 내용 수정 | 규칙 추가, 스킬 업데이트 |
| **문서 작성** | Confluence 페이지 생성·수정, README 작성 | 연구 기록, 문서화 |
| **Git 작업** | 커밋·브랜치·diff 분석 | 커밋 메시지 작성, 변경 사항 정리 |

### Sonnet 위임 금지 조건 (Opus 직접 처리)
- 수식 구현 포함
- 도메인 타당성 판단 포함
- 아키텍처 인터페이스 변경 수반
- 원인 분석이 아직 완료되지 않은 디버깅

## 3. Haiku subagent 위임 조건

**판단 기준**: 로직 판단, 사용자 승인, 도메인 특화 검증이 전혀 불필요한 작업

| 카테고리 | 구체적 조건 | 예시 |
|----------|-----------|------|
| **코드 검증** | syntax/import 오류 확인, lint 결과 해석 | flake8·mypy 출력 확인 |
| **파일 탐색** | 파일·함수·클래스 위치 검색 | Glob/Grep으로 심볼 찾기 |
| **단순 수정** | 변수명·경로·주석 변경, 오타 수정 | config 경로 수정, 주석 추가 |
| **반복 수정** | 동일 패턴을 파일 3개 이상에 일괄 적용 | 여러 파일에 동일 import 추가 |
| **소형 함수 수정** | 5줄 이하 단일 함수 수정 (수식·아키텍처 무관) | 단일 분기 추가, return 값 변경 |
| **테스트 실행** | 이미 작성된 테스트를 **실행만** 하고 PASS/FAIL 정리 (판정 로직 없음) | pytest 결과 요약. ※검증 판단(6-Gate·인과 트레이싱·FAIL 원인 분석)이 걸리면 Haiku 아님 → qa(sonnet) 소관 — `agents/qa.md` (2026-07-17 Codex C4 경계 명시) |
| **로그 분석** | 에러 로그 파싱 및 수치 추출 | 학습 로그에서 최저 loss 추출 |
| **포맷 변환** | 로직 없는 단순 포맷 변환 | json↔yaml, 들여쓰기 통일 |
| **Dry-run 확인** | 실행 없이 출력만 확인 | argparse --help 확인 |
| **의존성 조회** | 패키지 버전·호환성 확인 | pip show, uv pip list |
| **설정 파일 탐색** | rules/skills/agents 파일 내용 읽기·검색 | 규칙 참조 확인, 중복 검색 |
| **단순 문서 수정** | 오타·경로·날짜 등 로직 무관 문서 수정 | MEMORY.md 인덱스 갱신 |

### Haiku 위임 금지 조건 (Sonnet 이상 필요)
- 새로운 로직·알고리즘 설계 또는 구현
- 도메인 타당성 판단 포함
- 수식 구현 포함
- 디버깅 (단순 실행이 아닌 원인 분석 포함)
- 사용자와 합의가 필요한 설계 결정
- 기존 함수 동작 변경을 수반하는 수정 (예외: 아래 "5줄 이하 단일 함수 수정" 단서 충족 시)

> **우선순위 규칙**: Haiku 충분 조건과 금지 조건이 동시에 해당하면 **금지 조건 우선** — Sonnet 이상 사용 (단, "5줄 이하 단일 함수 수정" 단서는 이 규칙보다 우선하는 명시적 예외)

> **5줄 이하 단일 함수 수정**: 수식 구현 ❌, 아키텍처 변경 ❌, 사용자 합의 ❌, 동작 변경이 해당 함수 밖으로 전파 ❌ — 4개 모두 미해당 시 Haiku 위임 가능 (planner 제안 D 적용). 이 단서가 없으면 §3 허용표의 "소형 함수 수정" 행(단일 분기 추가·return 값 변경)이 금지 조건("동작 변경")에 항상 흡수되어 무력화되므로, 국소 동작 변경은 허용으로 명시한다.
